# 棋类小游戏（QQ 官方机器人）

基于 [QQ Official Hub](https://github.com/204343414/astrbot_plugin_qqofficial_hub)
的一次性卡片，全程由按钮点击驱动。支持**人机对战**与**群友对战**。

> 依赖：先安装并启用 `astrbot_plugin_qqofficial_hub` **v0.9.0 以上**，且开启其
> 「Interaction 兼容桥」并完整重启 AstrBot。
>
> 若提示「未找到 / 未启用 / 版本过旧」，可打开 Hub 的 **运行诊断** 页核对：
> 本插件注册成功时，会在「已注册 Action」里以 `astrbot_plugin_tictactoe`
> 分组出现并标注「外部插件」。

## 安装

在 AstrBot 插件市场填入仓库地址：

```
https://github.com/204343414/astrbot_plugin_Tic-Tac-Toe
```

> ⚠️ 若你在 v0.1.0 之前装过本插件，旧的 `metadata.yaml` 里 `repo` 字段指向了
> 一个不存在的仓库名，AstrBot 更新时会读**已安装的**那份 metadata
> （`updator.py`: `repo_url = plugin.repo`），于是永远 404 —— 修复在新版本里，
> 但要更新才能拿到新版本，形成死锁。请先卸载再按上面的地址重装。

## 玩法

聊天命令：

```
/井字棋          # 打开井字棋卡片
/五子棋          # 打开五子棋卡片
/斗兽棋          # 打开斗兽棋卡片
/下棋 5          # 井字棋落子（不依赖按钮）
/棋盘            # 重新出一张五子棋棋盘图（发图失败后用）
```

**每个游戏有自己的卡片，长得一模一样**，都是固定五个按钮：

```
[🤖 人机对战] [👥 群友对战]
[  轻松  ] [  普通  ] [  困难  ]
```

没有「总大厅」——`/井字棋` 不是五子棋的入口，反之亦然。这套布局由
`games/lobby.py` 的 `GameSpec` 统一生成，新游戏只要声明一个 `GameSpec`
并实现 `<key>.start_ai / start_pvp / set_level / join / quit`，卡片就与现有游戏
逐像素一致。难度**按群按游戏**分别记忆（井字棋困难 + 五子棋轻松可以并存）。

### 五子棋：图片棋盘 + 引用落子

15×15 = 225 格，而 QQ 键盘上限是 5×5=25，按钮方案不可能。因此五子棋渲染成
**图片**，玩家**引用棋盘图**回复坐标（如 `H8`）落子。

- 必须**引用**才算落子——否则群里聊到 "H8" 会被误判为走棋；
- 但引用的 id 与棋盘 id 对不上时**仍然放行**并记一条日志：QQ 发图时回传的
  消息 id 和它在引用里报回来的 id 并不总是同一个，为此吞掉玩家的一手远比
  误认一次引用糟糕（这正是"引用图片回 H8 没反应"的原因）；
- 提示语「引用本图回复坐标落子」只画在**图片里**，正文不再重复一遍；
- 发图失败（QQ 偶发 500「系统繁忙」）时**这一手仍然算数**，并提示用 `/棋盘` 重新出图；
  Hub 侧已对 5xx 退避重试 3 次，三次都失败才会走到这里；
- 图片里画出双方头像（`thirdqq.qlogo.cn`，用 AppID + member_openid 拼接），
  并用红圈标出当前回合方，最后一手打点，五连高亮；
- 头像**按对局缓存**，一局只下载一次。

### 字体：随插件打包，无需任何安装

`assets/fonts/wqy-microhei.ttc`（文泉驿微米黑，Apache-2.0，5.2 MB，覆盖 GBK 全部汉字）
**直接打进插件**。Docker 里也好、裸机也好，中文一律正常，不需要 `apt-get` 任何东西。

系统字体仍然优先：宿主机若装了 Noto / 思源，观感更好就用系统的，内置字体只作兜底。
插件会**实际验证**字体能否画出汉字（只看尺寸不够——缺字形的字体照样画出"豆腐块"，
判据是把字形位图和私有区码位比对）。

> 早先的做法是找不到中文字体就把整个界面降级成英文。这在官方 Docker 镜像上几乎必然
> 触发，结果就是"为什么我的棋盘是英文的"。把 5 MB 的问题甩给用户去装字体包是错的，
> 现在**不存在英文降级路径**。

### 斗兽棋

9 列 × 7 行的横版棋盘（等价于传统 7×9 旋转 90°），红方在左、蓝方在右，红先。

**棋盘是一张卡片：图和按钮在同一条消息里。** 走棋就是
「点动物 → 点方向 → 发送」，例如点「鼠」再点「⬇️ 下」，输入框变成 `鼠 下`，
自己按发送。双方各有一只同名动物，所以说「鼠」不会有歧义；
直接打字 `鼠下`、`老虎 上` 同样有效。

几个刻意的选择：

* **按钮是 type=2（插入文本，不发送）**，不是 type=1 回调。回调有冷却和延迟，
  而回合制游戏是要连点的；更要紧的是回调不产生用户消息，被动回复窗口会慢慢饿死。
  点了不发送还有个好处：点错能改。
* **只显示场上还活着的动物**。被吃掉的动物按钮必然被拒绝，而每条拒绝都要花一次
  回复配额。顺序固定按等级排，免得按钮在两回合之间挪到手指底下。
* **按钮带 `reply`**，所以发出去的消息自动引用棋盘卡——这就是「这步棋是针对
  这个局面走的」与「有人在群里随口说鼠下」的区别。
* **每行最多 4 个**：QQ 允许 5 个，但第 5 个会把标签文字挤掉（实测，非推测）。

> 斗兽棋**需要 Hub 图床**（卡片里的图必须是公网 URL）。图床不通时不会降级成
> 老的「发图片+引用」模式，而是直接拒绝开局并说明原因——按钮无声消失比开不了局
> 更难排查。管理员用 `/诊断` 看图床状态。

已实现的规则（每条都有独立测例）：

| 规则 | 说明 |
| --- | --- |
| 等级 | 象>狮>虎>豹>狼>狗>猫>鼠，同级可互吃 |
| 鼠吃象 | 鼠能吃象，象不能吃鼠 |
| 水陆隔离 | 只有鼠能下水；岸上吃不到水里的鼠，水里的鼠也吃不到岸上的象；两鼠在水中可互吃 |
| 狮虎跳河 | 横竖直线跳过整片河面落到对岸，可直接吃对岸较弱的兽 |
| 鼠挡路 | 河中有鼠（**不分敌我**）则狮虎不能跳 |
| 陷阱 | 进入**敌方**陷阱即失去战斗力，任何兽都能吃；自己的陷阱无影响 |
| 兽穴 | 不能进自己的兽穴；进入敌方兽穴立即获胜 |
| 其它胜负 | 吃光对方、或对方无子可动 |

**AI**：minimax + alpha-beta，吃子按价值排序以提升剪枝。评估 = 子力 + 逼近敌方
兽穴的距离 + 陷阱惩罚，获胜分**按步数折扣**（否则"一步入穴"和"三步入穴"同分，
AI 会站在兽穴旁边原地打转——这是实测抓到的真 bug）。

实测 28 局自我对弈，**100% 以「攻入兽穴」结束，零局靠吃光对手**——因为
`WIN_SCORE` 是全部 8 子材料和的 **513 倍**，加上步数折扣，直插兽穴永远压过慢慢吃子。

### 试过但撤掉的两个"优化"

写下来是因为它们**看起来都很有道理**，实测却站不住。没有记录的话，
过几个月又会有人（包括我）重新想出来一遍。

| 改动 | 实测结果 | 结论 |
| --- | --- | --- |
| 鼠与象等值（鼠能吃象，估值理应平起平坐） | 24 局交替先手 **13:11** | 与噪声无异，不改 |
| 地形感知距离（BFS 真实步数，替代曼哈顿距离） | 深度3 **13:11**、深度5 **6:6**；开局耗时 0.71s→**17.4s** | 不变强反变慢，回滚 |

第二条尤其值得记：曼哈顿距离会**直接穿过河**，所以狼站在河边会被算成"快到家了"，
而它其实要绕远路——听上去是明摆着的 bug。改成 BFS 真实步数后地图确实更准
（狮虎跳河最远 8 步 vs 陆生 11 步），**但胜率毫无变化**。

代价却是真的：评估值变连续 → alpha-beta 剪不动 → 深度 5 从 0.71 秒涨到 **17.4 秒**。
补了移动排序才压回 0.87 秒，可仍然没换来任何棋力。

`tests/test_animalchess.py` 里有对应测例锁住这些结论，包括一条**困难档必须
5 秒内出手**的性能回归守卫。

搜索深度实测（开局最坏情况）：深度 5 约 0.7 秒，深度 6 骤增到 4.3 秒，深度 7 要 16 秒。
因此困难档止步深度 5。自对弈 16 局（轮流先手）**困难 15:1 胜普通**，梯度是真的。

#### 素材替换

`assets/animalchess/` 下是**占位空图**，直接覆盖同名文件即可，代码零改动：

```
assets/animalchess/board.png              2135 × 1436，9×7 无留白
assets/animalchess/pieces/{rat,cat,dog,wolf,leopard,tiger,lion,elephant}.png
```

棋子**红蓝共用同一张图**，颜色由代码画的外圈区分。图片**按原比例缩放**（fit，不拉伸）后
居中放进正方形格位：非 1:1 的素材不会被压扁，同时每颗棋子在棋盘上的占位保持一致。
（实测素材宽高比在 1.00~1.58 之间，强行拉方会明显变形。）

棋盘输出为 **JPEG**（`file_type=1` 同时接受 png/jpg）。水彩底图用 PNG 存要 1.1 MB，
JPEG q85 只要约 180 KB 且看不出差别——每走一步都要重传，体积直接关系到响应速度，
也更不容易撞上 QQ 富媒体接口的「系统繁忙」。格子尺寸由图片尺寸整除得出
（2135/9 = 237.222，1436/7 = 205.143），全程用浮点累加、只在绘制时取整，
避免逐列累积偏移。若将来换成**有留白**的棋盘图，只需改 `animalchess_render.py`
顶部的 `GRID_LEFT` / `GRID_TOP` 四个常量。

没有素材时**不会崩也不会空白**：插件会用同样的几何画出棋盘并以文字代替棋子
（就是当前占位状态的效果）。全透明的占位图被视为「没有素材」，否则棋盘会渲染成一片空白。

### 只留一张卡（自动撤回）

图片棋盘每回合都要重发，按钮卡片（大厅、切难度、等待、井字棋棋盘）也是每次点击都重发，
一局下来会在群里堆几十条。现在**发出新的就撤回它替代的那一条**，屏幕上始终只有最新状态。

覆盖范围：斗兽棋/五子棋的图片棋盘、井字棋棋盘、三个游戏的大厅卡、切难度、等待对手卡。

同一个群、同一个游戏的整条入口链路共用一个会话（`ui:<游戏>:<群>`），所以
「大厅 → 切难度 → 等待 → 棋盘」会原地替换。**不同游戏各用各的会话**：别人正在看
井字棋的卡，你开五子棋不会把它撤掉。

- 需要 Hub ≥ v0.16.0（`hub.recall_message()`）；旧版 Hub 只是留着多余图片，不会出错；
- QQ 只允许撤回 **2 分钟内**的消息，超时静默跳过——所以慢节奏对局仍会留下历史棋盘；
- **先发新图、再撤旧图**：反过来一旦发送失败，群里连一张棋盘都没有了；
- 撤回失败完全不打扰玩家（这一手早已生效），只记 debug 日志；
- **终局那张卡不会被回收**，因为「🔄 再来一局」就在上面。只有显式「结束对局」或开下一局
  才会连卡片一起作废。

### 每群一局 + 闲置解散

同一群同时只允许**一局**进行中（井字棋、五子棋、斗兽棋等所有游戏共用这一个名额），避免"我在回复哪张棋盘"产生歧义，也控制被动消息用量。
超过 `idle_timeout_seconds`（默认 90 秒）无人落子则自动解散并释放对局位。

### 三段式卡片流程

这套结构可以被任何桌游插件直接套用：

| 阶段 | 卡片 | 说明 |
| --- | --- | --- |
| 大厅 | `lobby.build_lobby_card(spec)` | 五按钮：人机 / 群友 + 三档难度 |
| 等待 | `lobby.build_waiting_card(spec)` | 仅群友对战：发起者已入座，等人点「🙋 加入对战」 |
| 对局 | 各游戏自己渲染 | 井字棋是按钮卡片，五子棋是图片 |

五子棋的群友对战也走等待卡：**有人入座后才画第一张棋盘图**，不为一局无人应战
的对局白花一条被动消息。

大厅与等待卡片**不锁归属**（谁都能开局、谁都能加入），只有棋盘按回合锁定当前玩家。

### AI 难度

井字棋在双方无失误时**必定平局**，所以一个不犯错的 AI 是打不赢的
（实测随机玩家胜率仅 1%）。因此 AI 会按难度概率性地故意走随机步：

| 难度 | 失误率 | 随机玩家实测胜率 |
| --- | --- | --- |
| 轻松 | 60% | ~31% |
| 普通 | 25% | ~12% |
| 困难 | 0% | ~1% |

**按钮只是快捷方式，规则在服务端。** 无论点按钮还是打 `/下棋 5`，都会经过同一套
`apply_move()` 校验；位置被占、不是你的回合、对局已结束都会被拒绝并给出原因。
这样即使按钮渲染失败、或有人伪造点击，规则依然成立。

或在 Hub 卡片编辑器里，把任意按钮的「点击后执行」设为
**🎮 井字棋** 或 **⚫ 五子棋** —— 插件启用后会自动出现在下拉框里，
点击即弹出对应游戏的卡片。

## 它如何满足 QQ 的限制

| 限制 | 应对 |
| --- | --- |
| 群主动消息每月 4 条 | 每次落子都作为**被动回复**发出，不消耗主动配额 |
| 被动回复 5 分钟 / 5 条 | 一次点击只回一张卡 |
| 按钮上限 5×5 | 棋盘 3×3 + 1 行控制按钮 = 4 行 |
| 同时点击 | 每格 `one_shot`，由 Hub 服务端加锁判定，先到先得 |
| 误点已落子的格子 | 只回 ACK（QQ 给点击者弹提示），**不发群消息**，不消耗被动额度 |
| 抢别人的回合 | 格子 `owner_openid` 锁到当前回合方，他人点击返回「现在不是你的回合」 |

## 为什么棋盘不能在编辑器里画

棋盘**每一步都在变**：已落子的格子要消失、归属要换人、终局要换成「再来一局」。
编辑器保存的是**静态**卡片，无法表达这些。因此棋盘由 `tictactoe.build_card()` 每回合
重新生成 —— 这正是 Hub 一次性卡片存在的意义。

编辑器里能做的是**入口**：把「开始井字棋」绑到你的功能面板按钮上，
或在正文里插入蓝色参数指令，点击后把命令写进输入框：

```markdown
<qqbot-cmd-input text="%2F%E4%B8%8B%E6%A3%8B%20" show="%F0%9F%8E%AF%20%E4%B8%8B%E6%A3%8B" reference="false" />
```

即 `text="/下棋 "`、`show="🎯 下棋"`（都需 URL encode），点击后用户自己补 1~9 再发送。
Hub 编辑器的「蓝色参数指令文本」区可直接生成，无需手写。

## 结构

| 文件 | 职责 |
| --- | --- |
| `games/lobby.py` | `GameSpec` 与共用的大厅／等待卡片。所有游戏的入口长相由此唯一决定 |
| `games/tictactoe.py` | 井字棋规则、AI、按钮棋盘 |
| `games/gomoku.py` | 五子棋规则、AI、坐标解析 |
| `games/gomoku_render.py` | 五子棋图片棋盘（PIL） |
| `games/animalchess.py` | 斗兽棋规则、AI（minimax + alpha-beta） |
| `games/animalchess_render.py` | 斗兽棋图片棋盘（PIL）；`banner=False` 供卡片使用，避免与卡片正文重复 |
| `games/session.py` | 每群一局的对局台账、闲置解散、头像缓存、引用 id 解析 |
| `assets/fonts/` | 打包的中文字体（Apache-2.0） |
| `assets/animalchess/` | 斗兽棋棋盘与棋子素材（占位图，可直接覆盖） |
| `main.py` | Hub 对接：注册 Action、发牌、命令入口 |

`games/` 下全部是纯逻辑，不依赖 AstrBot 与 Hub，可单独测试。

玩家昵称由 `main.py` 在发牌前查 Hub 的身份台账，注入 `state["labels"]`；
规则模块只读这个字典，因此不必依赖 Hub。**任何情况下都不会显示原始 OpenID**，
未知玩家显示为「玩家…后4位」。

AI 采用「能赢就赢 → 能堵就堵 → 中心/角 → 随机」的简单策略，不是 minimax，
但至少不会视而不见地送掉一局。

### one_shot 用在哪、不用在哪

Hub 会在**业务逻辑运行之前**消费掉 one-shot 按钮。因此它只适合「这个操作本身
不可重复」的场景，不能用来表达「这个席位只有一个」：

| 按钮 | one_shot | 原因 |
| --- | --- | --- |
| 棋盘格子 | ✅ | 同一格重复落子确实非法 |
| 🙋 加入对战 | ❌ | 房主误点一次就会烧掉席位，别人再也加入不了 |
| 🔚 结束 / 🔄 再来一局 | ❌ | 路人误点一次就没人能结束或重开了 |

席位是否被占、对局是否结束，都由 handler 依据**游戏状态**判断，重复点击返回
ACK 提示（只有点击者可见，不发群消息）。

归属方面：等待中的「取消」只有房主可点；单人对局的「结束」只有本人可点；
终局的「再来一局」所有人可点。

### 会话回收

`end_ephemeral_session()` 会删除**整个 session 的所有卡片**。因此每次打开大厅前
都会先 `_retire()` 掉本群残留对局——否则旧对局收尾时会连带把刚发出的大厅卡作废，
表现为点按钮提示「卡片不存在或已过期」。

### 更少的消息

- 对局中正文只有一行状态，棋盘由按钮呈现，不再重复渲染；终局无按钮时才在正文显示棋盘；
- 只剩最后一格时自动落子，不再为一个没有选择余地的操作多发一张卡；
- 误点已落子的格子只回 ACK，群里不会多出消息。

### 棋盘始终是 3×3

已落子的格子**不会消失**，而是变成显示棋子（⭕/❌）的灰色占位按钮。
若按可落子数量动态收缩，每走一步布局都会变形，玩家极易点错。
误点占位按钮时只返回 ACK code，QQ 只给那一个人弹提示，群里不会多出任何消息。
